# API DOCS

## File `users.js`:

@brief Stores users in memory and provides functions to create, read and remove them.

User structure:

```js
{
  id: "alice",
  name: "Alice"
}
```
___
Function `createGuest()`:

@returns A new user copy with a server-generated UUID and the name `"Guest"`.
No arguments are required. The function generates another UUID while the ID
already exists in `users`, then stores the guest through `createUser()`.
`POST /api/createUser` calls this function without reading a request body.

___
Function `createUser(userId, userName)`:

@param `userId` Nonempty string ID for the new user.
@param `userName` Nonempty string containing the user's name.
@returns User copy.

Invalid fields throw `INVALID_USER_ID` or `INVALID_USER_NAME` before saving
anything. A duplicate ID throws `USER_ALREADY_EXISTS`. This helper still accepts
explicit fields, while the guest endpoint uses `createGuest()`.

Function `getUser(userId)`:

@param `userId` User ID.
@returns User copy or `undefined`.
___
Function `getUsers()`:

@returns Array of user copies. No arguments are required.
___
Function `removeUser(userId)`:

@param `userId` ID of the user to remove.
@returns `undefined`; removes the user entry.
___
Guest IDs are generated by the server. These functions do not create SQL accounts.
Removing a user does not remove their player object from existing games.
