# Гаджеты

Гаджеты применяются только в свой ход в фазе `battle`. Каждый из трёх гаджетов
доступен один раз за матч. Успешное действие добавляет его имя в
`players.you.usedGadgets`, но не завершает ход. Ошибка ничего не расходует.
Робот автоматически стреляет после промаха человека и сам гаджеты не применяет.

## HTTP

```http
POST /api/games/:gameId/gadgets/:gadget
userId: <id игрока>
Content-Type: application/json
```

`:gadget` принимает `radar`, `mine` или `relocate`. Ответ HTTP 200 содержит
актуальный персональный вид игры, как `GET /api/games/:gameId`.
Все подписанные сокеты получают свой `game:state`. Координаты начинаются с нуля.

## Сканер

Тело запроса для `radar`:

```json
{"row": 4, "col": 4}
```

Это центр квадрата 3×3 на поле соперника. На краю включаются только существующие
клетки. Сервер возвращает все клетки области, включая воду, в
`players.you.scannedZones`. Например, часть массива выглядит так:

```js
scannedZones = [
    {row: 3, col: 4, hasShip: true},
    {row: 4, col: 4, hasShip: true},
    {row: 5, col: 4, hasShip: false}
]
```

В середине поля массив содержит девять элементов, в углу четыре.
`hasShip` означает наличие палубы, включая уже повреждённую.
Это снимок на момент сканирования. Перемещение соперника не обновляет его.
Вид соперника не содержит чужих `scannedZones`, `mine` или `usedGadgets`.

## Мина

Тело запроса для `mine`:

```json
{"row": 0, "col": 0}
```

Мина ставится на своё поле. На клетке не должно быть своего корабля, в том числе
повреждённого, или предыдущего выстрела соперника. Сервер хранит и возвращает
владельцу `players.you.mine = {row, col, triggered: false}`.

Если соперник стреляет в мину, исходный выстрел получает результат `miss`, потому
что мина стоит на воде. Дополнительно сервер ставит `mineTriggered: true` и
отражает выстрел по тем же `row` и `col` на поле стрелявшего. Вода даёт `miss`,
палуба `hit` или `sunk`. Пример результата для стрелявшего игрока:

```js
{
    row: 0,
    col: 0,
    result: "miss",
    mineTriggered: true,
    reflectedShot: {
        row: 0,
        col: 0,
        result: "hit",
        source: "mine",
        playerId: "mine-owner",
        opponentId: "shooter"
    },
    playerId: "shooter",
    opponentId: "mine-owner",
    phase: "battle",
    turnPlayerId: "mine-owner",
    winnerPlayerId: null
}
```

При потоплении `reflectedShot` также содержит `cells`. Отражённый выстрел может
завершить матч победой владельца мины. Тогда `phase` равен `finished`,
`turnPlayerId` равен `null`, а `winnerPlayerId` содержит ID владельца мины.
Если матч продолжается, ход получает владелец мины.

Исходный выстрел с флагом сохраняется в `shots` стрелявшего. Отражённый выстрел
с `source: "mine"` сохраняется в `shots` владельца мины. Поэтому у каждого
участника есть данные для отметок и на своём поле, и на поле соперника.
После срабатывания `mine.triggered` становится `true`.

Уже обстрелянная клетка повторного урона не получает. В таком случае
`reflectedShot.alreadyShot` равен `true`, возвращается прежний результат,
а повторная запись в историю не добавляется. Отражение не активирует другую
мину. За один обычный выстрел происходит не больше одного отражения.

## Перемещение

Тело запроса для `relocate` совпадает с полями текущей кнопки Гоши:

```json
{
    "oldRow": 8,
    "oldCol": 6,
    "newRow": 8,
    "newCol": 8,
    "isVertical": false
}
```

`oldRow` и `oldCol` могут указывать на любую палубу выбранного своего корабля.
`newRow` и `newCol` задают начало нового положения. `isVertical` задаёт ориентацию.

Перемещать можно только полностью целый корабль. Он должен помещаться на поле,
не пересекать и не касаться остальных кораблей, включая диагонали.
Нельзя занимать свою мину и клетки, по которым соперник уже стрелял.
Перенос на прежнее место отклоняется без расходования гаджета.
При успехе меняются только координаты выбранного корабля. Урон остальных,
истории выстрелов и текущий ход сохраняются.

## Socket.IO

Применение гаджетов выполняется только через HTTP. Socket.IO доставляет
персональные обновления `game:state` после успешных действий, как после выстрела.
Подписка `game:subscribe` и идентификация через `socket.handshake.auth.userId`
остаются прежними.

Frontend берёт `scannedZones`, `mine` и `usedGadgets` из `players.you` в HTTP-ответе
или в `game:state`. Сокет-команд `useRadar`, `placeMine`, `relocateShip` и отдельного
события `radarResult` нет. Ошибки применения приходят в обычном HTTP-ответе
`{error: {code, message}}`.

## Ошибки

- `INVALID_GADGET`, HTTP 400: неизвестное имя гаджета.
- `INVALID_GADGET_TARGET`, HTTP 400: недопустимая клетка или перенос.
- `GADGET_ALREADY_USED`, HTTP 409: гаджет уже применён.
- `PLAYER_NOT_IN_GAME`, `BATTLE_NOT_ACTIVE`, `TURN_MISMATCH`: обычные ограничения
  участника, фазы и хода из [описания ошибок](errors.md).
